# Android 학생증 QR

설정의 내 정보 카드 오른쪽 QR 버튼으로 연다. Android 앱에만 표시한다.
현재 계정의 학교 로그인 정보를 기기 보안 저장소에서 읽으므로 자동 로그인이 필요하다.
홍시 서버와 DB는 이 기능에 관여하지 않는다.

처음 발급, 새로고침, 오류 안내에도 288px 정사각형 QR 자리를 유지한다.
QR이 없을 때는 점선 테두리의 빈칸으로 표시하고, 요청 중 새로고침 버튼은 비활성화한다.
오류 안내는 문장마다 줄을 바꾼다. QR 아이콘은 사용자가 제공한 형태를 인라인 SVG로 구현한다.

## 확인한 연동 경로

2026-10-08에 남겨진 Heyoung 1.6.9 공개 웹 클라이언트와 독립 로그인 실험을 근거로 구현했다.
호스트는 `https://campus.heyoung.co.kr:18091`로 고정하며 각 서비스에 JSON으로 POST한다.
다른 호스트로 리디렉션하지 않고 Android의 기본 TLS 인증서 검증을 사용한다.
초기화 응답에는 전체 다국어 사전이 포함되어 실제 크기가 약 1.94MB였다.
초기화 서비스만 최대 8MiB를 허용하고, 나머지 서비스에는 1MiB 제한을 적용한다.
공식 클라이언트의 `localeVersion` 규약으로 불필요한 다국어 사전 전송을 생략한다.
최초 요청에는 확인된 공개 버전 `20261006173647`을 사용하고 이후에는 서버가 반환한 버전을 저장해 사용한다.
버전이 바뀌면 서버가 새 사전과 버전을 내려주며, 이때도 위 응답 제한을 적용한다.

| 순서 | 서비스 | 역할 |
| --- | --- | --- |
| 1 | `HCO0201S01` | `HIUV`, Android 초기화 및 `RES_DAT.enckey` 수신 |
| 2 | `HCO0112S02` | 로그인 초기화 |
| 3 | `HCO0204S01` | 학교 계정으로 새 세션 생성 |
| 4 | `CMM0101S05` | `MOBILE_TIMER`, `G.CODE` 학생증 타이머 설정 조회 |
| 5 | `HCO0501S03` | `RES_DAT.qrcode` 발급 및 갱신 |

모든 요청은 `REQ_COM`(serviceId, screenId, langCd, clientAgent, clientOS, univCd)과
`REQ_DAT`으로 구성한다. 로그인 암호화는 서버의 96자 challenge를 분리해
PBKDF2-HMAC-SHA1(1,000회, 256비트)과 AES-CBC/PKCS 패딩을 적용하는 기존 클라이언트 규격을 따른다.
서버 제공 salt/IV를 사용한다. 설치별 무작위 device ID를 만들며 공식 앱의 식별자·세션을 복사하지 않는다.

로그인 응답 `000`과 `002`에서 QR 발급을 진행한다. `002` 처리에는 사용자가 제공한
헤이영 측 확인 내용을 반영했다. `002`를 전체 본인인증 완료로 보고하지 않는다.
응답의 `data.idno`가 현재 홍시 계정과 일치해야 QR 발급을 진행한다.

## 유효시간과 상태 정리

공식 `HCO0401P01` 화면은 `CMM0101S05`의 `data[0].code2`를 초 단위로 사용한다.
설정이 없거나 양수가 아니면 공식 화면과 동일하게 30초를 사용한다.
QR 응답의 `cnt`는 만료 시간으로 해석하지 않는다.

네이티브에서는 `elapsedRealtime`, 화면에서는 `performance.now`로 남은 시간을 계산한다.
네이티브는 QR 요청·렌더링 시간만 차감하며 화면은 추가 IPC 전달 지연만 차감한다.
QR 발급 전 로그인 시간은 새 QR의 유효시간에서 빼지 않는다. 만료 시 기존 QR을 숨긴 후 새 QR을 요청한다.
요청 실패 시 자동으로 비밀번호 로그인을 반복하지 않으며 사용자가 다시 시도할 수 있다.

창 닫기와 백그라운드 전환 시 QR 표시를 지우고 진행 중인 요청을 취소한다.
이미 발급까지 완료한 동일 계정의 로그인 세션은 메모리에만 보관해 다시 열거나 복귀할 때 재사용한다.
QR 값 자체는 재사용하지 않고 매번 새로 발급한다. 마지막 성공 후 5분이 지난 세션,
서버에서 거절된 세션, 로그아웃·계정 변경 시의 세션은 폐기한다.
5분은 클라이언트의 재사용 제한이며 서버 세션의 실제 만료시간을 의미하지 않는다.
창마다 고유 ID를 두어 닫힌 창의 늦은 응답을 버린다.
비밀번호·세션 쿠키·QR 원문을 로그에 쓰지 않고 프런트엔드에는 PNG와 남은 시간만 반환한다.

`HongsiQrTiming` 진단에는 요청 순번과 단계별 밀리초, 응답 크기만 남긴다.
학교 계정 확인, 큐 대기, HTTP 응답 대기·읽기·JSON 해석, 비밀번호 암호화,
QR 이미지 생성과 전체 표시 소요시간을 구분하며 계정·비밀번호·쿠키·QR 원문은 포함하지 않는다.

## 검증 범위

빌드 및 로컬 단위 검증은 실제 계정의 QR 발급이나 리더기 인식 검증과 구분한다.
실제 기기에서 로그인·QR 표시·갱신·복귀·리더기 동작은 사용자가 직접 테스트한다.
최초 가입·학생증 등록, 자연 세션 만료 시간, 토큰 기반 자동 재인증은 구현 범위에 포함하지 않는다.

Git 조회 없이 빌드하려면 `HONGSI_BUILD_COMMIT=''`를 지정한다.
기존 설치의 서명을 확인한 후 같은 키로 서명하고 `adb install -r`로 설치한다.
